===============================================================================
3. OWNERSHIP / LAZINESS
===============================================================================

- G08 printing lives in graphium.adapters.gtk, not GraphiumCore/application/domain infrastructure.
- graphium.adapters.gtk.printing (final module name may vary only mechanically) is NOT imported by
  window.py at module import time.
- GraphiumWindow may hold only a None lazy reference before first print-family activation.
- First Page Setup/Preview/Print activation constructs the print controller and loads Page Setup.
- No PrintOperation survives an operation; create one per Preview/Print invocation.
- No worker, thread, timer, idle service or background queue.

===============================================================================
4. PAGE SETUP AUTHORITY
===============================================================================

Persistence:
  XDG_CONFIG_HOME/graphium/page-setup.ini
  product-local, mode 0600, complete-temp + atomic replace.
  GTK native GtkPageSetup file serialization is the payload authority; Graphium owns location,
  lifecycle and acceptance semantics rather than reimplementing paper-size internals.

Load:
  first print-family action only.
  missing/corrupt/unreadable => fresh Gtk.PageSetup default, no automatic repair write.

Page Setup action:
  opens GTK's standard Page Setup dialog against a copy/current accepted setup.
  Cancel => exact no-op.
  Accept => persist candidate first; only after persistence succeeds publish it as active setup.
  Persistence failure => warning; prior active setup remains authoritative.

Print/Preview never need to write Page Setup in the frozen v1 model; Page Setup is changed through
its dedicated command. This avoids duplicate configuration surfaces.

===============================================================================
5. PRINT SETTINGS
===============================================================================

GtkPrintSettings is process-memory convenience only in G08.
  - start with a fresh Gtk.PrintSettings on first print-family use;
  - Print APPLY may retain a copy for the next Print/Page Setup in the same process;
  - Cancel/Error/Preview do not advance it;
  - no persistent printer selection/copies/backend state file in G08.

===============================================================================
6. CONTENT SNAPSHOT / RENDERING
===============================================================================

On Preview/Print activation capture once:
  - exact live GtkTextBuffer text;
  - display title = basename of active logical path, else Untitled;
  - persistent base font family + base point size (NOT transient Zoom).

Rendering:
  - GtkPrintOperation;
  - Pango layout + Cairo through GtkPrintContext;
  - page-width word/character-safe wrapping independent of screen Word Wrap;
  - preserve ordinary text/newlines/tabs as rendered plain text;
  - minimal fixed title and page-number information;
  - no line-number gutter, syntax colors, theme background or editor chrome.

Pagination authority:
  Pango layout geometry under the actual GtkPrintContext, grouping complete visual layout lines into
  pages. Do NOT derive pages from Python splitlines(), a fixed characters-per-page rule or screen
  viewport geometry. Do not split a visual Pango line across page boundaries.

===============================================================================
7. MODAL / LIFECYCLE CONTRACT
===============================================================================

Page Setup / Print / Preview are parented to the active GraphiumWindow.
Print operation is synchronous by default; no allow_async/worker lifecycle is pre-authorized.
Native GTK owns the preview UI. Graphium does not intercept the preview signal to create a custom UI.

Cancel:
  no warning, no state mutation.
Error:
  show one Graphium error surface; restore editor usability/focus.
Success:
  release operation/layout references before returning to normal editing.
Repeated operations:
  each uses a fresh GtkPrintOperation; no stale callback/layout/page count survives.

===============================================================================
8. DOCUMENT / FILE NEUTRALITY — HARD GATE
===============================================================================

Before and after Page Setup / Preview / Print (success, cancel or error), except the explicitly
accepted Page Setup config or in-process print-settings convenience:
  buffer text identical;
  logical/canonical document binding identical;
  accepted DocumentFileState identical;
  current editor state ID identical;
  saved editor state ID identical;
  Saved/Modified identical;
  DeltaHistory/Undo/Redo identical;
  Recent identical;
  target document bytes on disk identical.

Printing a Modified or Untitled document is allowed and prints the current live snapshot without Save.

===============================================================================
9. STARTUP-ISOLATION GATE
===============================================================================

Static/runtime boundaries:
  - no top-level import of the print implementation from normal startup modules;
  - after GraphiumWindow construction, print implementation module absent from sys.modules;
  - zero GtkPrintOperation/GtkPageSetup print-controller creation before user action;
  - zero page-setup path read/stat/mkdir/write before user action.

Hostile dormant-state tripwire:
  A fresh isolated XDG config may place a named FIFO at the future page-setup path. Normal Graphium
  startup/open/FIRST_EDITABLE must complete without touching/blocking on that FIFO.

Performance protocol:
  - one uncounted priming process + >=7 fresh measured processes per workload;
  - same FIRST_EDITABLE/FIRST_VISIBLE ownership rules already frozen in G04/G06;
  - must continue to pass permanent G04 self-regression limits;
  - additionally compare exact G08 candidate against a fresh same-session published-G07 reference.

Incremental dormant-print limits versus fresh published G07 medians:
  time: <= max(G07 * 1.10, G07 + 25 ms)
  RSS:  <= max(G07 * 1.10, G07 + 8 MiB)
  workloads: empty, 5KiB, 1MiB, 10MiB where the existing oracle supports them.

Common FIRST_VISIBLE comparator receipt against Leafpad/L3afpad/Mousepad/FeatherPad remains required;
no cross-product FIRST_EDITABLE claim before G12.
