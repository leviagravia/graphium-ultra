BASELINE FACTS
- Active GTK history is DeltaHistory, not G02 TextHistory snapshots.
- Native edits are captured from Gtk.TextBuffer insert/delete signals.
- G04 renderer-safety guards run before default insert/delete mutation.
- NativeEditorController suppresses signal re-recording only while restoring/loading.
- GtkTextBufferPort.apply_replay already provides expected-delete verification plus inverse rollback.
- The current command catalog owns File/Edit/Help actions and accelerators.
- Current composition has exactly one document/session/history/editor/writer/lifecycle authority.

G05 INTEGRATION RISKS FOUND
1. A naive Replace All loop can create many GTK mutations while pretending one logical edit.
2. begin/end-user-action groups user-visible operations but is not an atomic rollback mechanism.
3. Generic suppression of G04 renderability guards would create a safety escape hatch.
4. Full-document snapshot history must not be reintroduced through legacy G02 editor_transaction.py.
5. Case-insensitive Unicode search cannot safely use ASCII-only folding.
6. Eager highlight-all/continuous rescanning would add background/document-wide work contrary to the Lightweight Budget.
7. Repeated replacements must be computed against the original source, not recursively against inserted replacement text.
8. Any precomputed replacement plan must be rejected if editor state identity has changed before application.

ARCHITECTURAL CONSEQUENCES
- Search algorithm is GTK-free and literal-only in G05.
- Search/replacement fields are single-line Unicode text; query must be non-empty; replacement may be empty.
- Search navigation captures text only on explicit command; no background scanner and no persistent search DB.
- Find/Find Next/Find Previous never alter state identity/history/Saved-Modified.
- Replace One and Replace All apply via a new bounded programmatic-delta transaction on NativeEditorController.
- Programmatic replacement is preflighted against final text renderability before GTK mutation.
- Existing G04 native edit guards remain authoritative for ordinary typing/paste/delete.
- No public/generic 'disable renderer safety' switch is introduced.
- Replace All operations are derived from original non-overlapping matches and applied in descending document offset order.
- Replace All is one DeltaHistory group/state-ID advance/Undo step; zero changes means no state advance.
- Programmatic buffer application uses expected-delete checks and inverse rollback; failure restores history/session authorities.

LEGACY CODE DECISION
- graphium/application/editor_transaction.py remains historical G02 regression code only.
- G05 MUST NOT route replacement through its full-snapshot transaction model.

POST-IMPLEMENTATION AUDIT — 2026-08-14
