Safety invariants
=================
- no direct document writer marker in GTK adapters;
- no G04 second file identity/session authority;
- Save/Save As remain bind-after-commit / stale-fail-closed via G03;
- Open loads before replacement;
- no implicit content normalization in G04;
- no whole-document capture per native edit;
- no semantic Undo timer;
- no GtkSourceView/tabs/toolbar/syntax/projects;
- Help content is local and loaded on explicit command only.

Failure-specific renderer-safety extension
==========================================
graphium/application/renderability.py
  GTK-free content-neutral admission policy.  A file may be valid G01 text but still be
  outside the bounded interactive Gtk.TextView renderer contract.  The current G04 budget
  is 20,000 Unicode characters per logical line.

graphium/application/file_lifecycle.py
  validates loaded text after G01 decoding but before NativeEditor/Buffer installation;
  over-budget Open leaves the current document/session/history exact.

graphium/adapters/gtk/window.py
  pre-default insert-text and delete-range guards prevent a currently safe document from
  being edited/pasted/joined into a pathological huge-line state.  Rejected mutations are
  stopped before GtkTextBuffer's default mutation and do not enter DeltaHistory.

tools/g04_true_gtk_gate.py
  separates realistic file size from pathological line width: a ~1 MiB multiline document
  is scrolled to the actual end and edited/undone, while an over-budget logical line is
  rejected before buffer installation and an over-budget insertion is blocked.

Additional safety invariants
============================
- document byte size alone is not an interactive-renderability oracle;
- large multiline file support and huge-line rejection are separate requirements;
- no hidden truncation marker, automatic wrap, automatic newline insertion or content
  normalization is permitted as a renderer workaround;
- no read-only fallback in the same Gtk.TextView is claimed safe for the observed failure
  class; exact paged/streamed viewing is future architecture, not G04;
- future line-budget changes require explicit renderer qualification rather than guesswork.
