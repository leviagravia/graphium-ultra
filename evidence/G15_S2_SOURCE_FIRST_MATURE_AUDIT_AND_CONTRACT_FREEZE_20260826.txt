CURRENT GRAPHIIUM BEHAVIOR
--------------------------
Edit -> Preferences… opens a modal dialog containing exactly:
  - Tab width: integer 1..32, default 8
  - Insert spaces instead of tabs: boolean, default false

The semantic settings authority is already correct and small:
  ViewSettings.tab_width
  ViewSettings.insert_spaces
  JsonViewSettingsStore persists the same two keys atomically in view.json.
  GraphiumTextView applies the width to Pango tab stops.
  Insert-spaces changes only future plain Tab key behavior and uses the configured
  logical next tab stop.

The problem is therefore UI topology, not a missing settings model.

CONFIRMATION-BIAS COUNTERMEASURE
--------------------------------
Graphium assumption under test:
  remove Preferences and expose tab controls directly.

Contradictory/stressing mature evidence:
  Mousepad and gedit duplicate direct tab controls in Preferences; GNOME Text Editor and
  FeatherPad keep tab size in Preferences. Therefore "mature editors put tab width directly
  in a menu" is NOT a universal rule.

Materially different mature model:
  rich editors justify Preferences because it is an aggregate surface for many setting
  families. Lightweight Leafpad/L3afpad demonstrate that tab-width control alone does not
  require such a surface.

Decision change caused by the contradictory evidence:
  Graphium must NOT copy Mousepad's duplication. The rationale for deleting Preferences is
  specifically Graphium's tiny two-setting surface and existing one-owner/direct-command
  policy, not an assertion that Preferences is generally bad.

ADOPT / ADAPT / REJECT / DEFER
------------------------------
ADOPT:
  - direct access to Tab Width;
  - direct checked access to Insert Spaces Instead of Tabs;
  - persistent settings across restart;
  - 1..32 custom tab-width capability;
  - narrow Other… selector rather than a generic Preferences dialog;
  - Cancel is state-neutral;
  - settings persistence failure does not publish a new UI/action state.

ADAPT:
  - Mousepad fixed choices 2/3/4/8 + Other…;
  - keep Graphium's existing ViewSettings/JsonViewSettingsStore authority;
  - place the two direct controls in Edit, matching the already approved Graphium surface,
    rather than copying Mousepad's Document topology. Graphium Document is currently reserved
    for representation/document inspection operations (Encoding, Line Endings, Check Spelling,
    Statistics), while these tab controls are persistent editor-input behavior.

REJECT:
  - retaining Edit -> Preferences… after direct controls exist;
  - duplicating the same two settings in both direct commands and Preferences;
  - moving tab width into document metadata or making it per-document;
  - adding GtkSourceView, GSettings, EditorConfig, modelines, plugin/config frameworks;
  - a 1..32 menu with 32 visible choices;
  - removing current custom-width capability;
  - adding a Tab Width keyboard shortcut in this slice;
  - changing existing document text when only display width changes;
  - rewriting existing literal tabs when Insert Spaces is toggled.

DEFER:
  - any future general Preferences surface. It may return only if Graphium later has enough
    independently justified settings that a consolidated preferences UI reduces rather than
    increases complexity. No such surface is justified now.

FROZEN SEMANTICS
----------------
TAB WIDTH
  - default remains 8;
  - valid persisted domain remains integer 1..32;
  - choosing 2/3/4/8 persists immediately, then updates the active text view;
  - Other… opens only a tab-width numeric chooser, initialized from current width;
  - cancelling Other… changes nothing;
  - custom values remain persisted and applied on restart;
  - a custom current value maps the menu state to Other…;
  - changing width changes visual/logical tab-stop behavior only; no document edit, no dirty
    transition, no history entry, no file mutation.

INSERT SPACES INSTEAD OF TABS
  - default remains false;
  - direct boolean menu action;
  - toggle persists immediately, then updates the active text view;
  - toggling alone does not edit the document, dirty it, or create history;
  - when enabled, a later plain Tab key inserts spaces to the next logical configured tab stop;
  - modified Tab combinations remain unrepurposed, preserving current behavior.

PERSISTENCE / AUTHORITY
  - ViewSettings remains sole semantic owner;
  - JsonViewSettingsStore remains sole persistence owner for these settings;
  - existing key names tab_width and insert_spaces remain unchanged;
  - no config migration and no compatibility reader is added;
  - failure to save keeps the previous in-memory authority, action state and TextView behavior.
