2. EXACT GRAPHIIUM SOURCE CAUSE

Pre-repair graphium/adapters/gtk/printing.py _PrintJob.begin_print did all document-size work in one
GTK callback:
  - create one Pango.Layout for the complete snapshot;
  - set complete document text on that layout;
  - force layout.get_line_count();
  - traverse every visual line via get_line_readonly()/get_extents();
  - derive every page boundary;
  - only then call set_n_pages() and return.

The observed heartbeat->BEGIN_PRINT_ENTER->containment sequence matches this ownership boundary.
No evidence supports an O(N^2) re-pagination bug; the failure is eager document-global work in one
main-loop callback.

4. REPAIR CONTRACT

Graphium retains:
  - native GtkPrintOperation Preview and Print dialog;
  - allow_async TRUE + one in-flight operation/job + done ownership;
  - Pango/Cairo rendering;
  - exact live PrintSnapshot;
  - page breaks only between complete measured Pango visual lines;
  - no GtkSourceView/GtkSourcePrintCompositor dependency;
  - no worker/thread/timer/queue/progress service/custom preview;
  - strict startup-lazy print-module and Page Setup boundary.

Graphium changes only pagination ownership:
  - begin-print becomes document-size-independent state/geometry initialization;
  - GtkPrintOperation paginate signal is connected;
  - each paginate callback measures at most one bounded Pango layout chunk;
  - chunk target = 16 KiB and maximum 64 logical source lines;
  - chunk boundaries occur only at logical-line boundaries, never inside a source logical line;
  - the existing G04 20,000-character logical-line renderability gate bounds the one-line fallback;
  - non-final chunks ending in newline suppress only Pango's artificial terminal empty visual line,
    preventing a blank line from being manufactured at chunk boundaries;
  - measured chunk layouts are retained only for the operation lifetime;
  - an incremental GTK-free paginator joins visual-line spans across chunk boundaries and commits
    pages only between complete measured visual lines;
  - set_n_pages() is published only after pagination completes;
  - draw-page renders retained Pango visual lines; it does not re-layout the whole document.
