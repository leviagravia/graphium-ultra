Mousepad obtains available spell languages from gspell_language_get_available(),
builds a user-visible model from language name + code, selects a default from
gspell_language_get_default(), and applies a chosen language through
 gspell_checker_set_language().

Mousepad persists a global plugin preference:
  plugins.gspell.preferences.default-language

Finding for Graphium:
- ADOPT: expose only languages/dictionaries that the backend says are available.
- ADOPT: retain a backend/system default.
- REJECT: add a persistent default-language setting merely to satisfy G15-S3.
  Graphium’s spelling operation is explicit and dialog-lifetime; a new persistent
  authority is not required by the user request.

======================================================================
5. HUNSPELL CLI AUTHORITY FINDINGS
======================================================================

Current Hunspell documentation defines:
- -D: show detected loaded dictionary path, search path and available dictionaries;
- -d dict[,dict2,...]: select dictionaries by base name with or without paths;
- a base dictionary consists of a matching .aff + .dic pair;
- System/default dictionary selection depends on locale when -d is absent.

Important robustness finding:
Hunspell -D textual output has changed across Hunspell versions. Therefore Graphium
MUST NOT parse localized/human headings such as “AVAILABLE DICTIONARIES”.

Frozen adaptation:
- run Hunspell’s own -D discovery only after explicit Check Spelling invocation;
- execute under LC_ALL=C;
- treat output as untrusted bounded diagnostic text;
- ignore headings/search-path prose entirely;
- accept a candidate only when an output line denotes a filesystem base path for
  which both <base>.aff and <base>.dic are regular files;
- reject malformed/unsafe candidates;
- deduplicate and stably sort;
- use the exact discovered base path as the -d argument, not a reconstructed
  hard-coded distro path.

This avoids duplicating Hunspell’s search-path authority while also avoiding a
version-sensitive parser for its human headings.

6. FROZEN G15-S3 PRODUCT CONTRACT
======================================================================

6.1 UI
------
The existing modal spelling dialog keeps its topology. The first row becomes:

  Dictionary: [ System default v ]

The combo contains:
1. System default
2. verified available Hunspell base dictionaries, typically displayed by their
   canonical dictionary IDs such as it_IT, en_GB, en_US.

No language-name mapping database is added. The Hunspell dictionary identifier is
the source-authentic UI identity. If duplicate basenames are discovered from
multiple paths, the UI must disambiguate them with parent-path context rather than
silently collapse distinct authorities.

6.2 Lifetime / persistence
--------------------------
Dictionary selection is DIALOG-LOCAL ONLY.

It is NOT:
- written to ViewSettings;
- written to another JSON/config store;
- written to document metadata;
- retained across application restart;
- auto-detected from document contents.

Rationale: this satisfies explicit language choice without creating a new persistent
configuration authority, and preserves the original G14 lightweight boundary.

6.3 Discovery
-------------
Discovery is optional and on-demand only. No import/startup/idle scan is permitted.

The existing single spell worker is reused for bounded discovery and later token
requests. Discovery must not create a second worker. At most one Hunspell child may
exist at a time: the short-lived -D child is fully reaped before a spell pipe child
may start.

Discovery failure/timeout does NOT disable System default. It degrades to:
  [ System default ]
and the existing system-default spell attempt remains available.

6.4 Selected session argv
-------------------------
System default:
  existing argv remains semantically identical; no -d argument.

Explicit dictionary:
  existing argv plus a separate argv pair:
    -d <verified-base-path>

shell=False remains mandatory. The dictionary path is never shell text and never
comes from an arbitrary editable field.

6.5 Changing dictionary while dialog is open
---------------------------------------------
Graphium keeps the current low-friction behavior: spell checking may begin using
System default once discovery has completed.

If the user changes Dictionary:
- invalidate/fence any old worker result;
- cancel, terminate/reap and close the old Hunspell session;
- ensure no old result can project into the UI;
- verify the editor has not changed outside the spell dialog’s owned edits;
- create a fresh SpellCheckController snapshot of the current editor text;
- create a fresh HunspellPipeSession with the selected dictionary;
- restart checking from the beginning under the new dictionary;
- reset dialog-local Ignore All state.

Previously applied Graphium Replace edits remain ordinary document edits and normal
Undo/Redo history. Dictionary selection itself never changes text, dirty/savepoint,
history or representation profile.

If the editor state changed externally/unowned, dictionary switching MUST NOT bypass
the existing stale-session fence; fail closed and require a new Check Spelling run.

6.6 No new capability framework
-------------------------------
G15-S3 must not add:
- new top-level module for external tools;
- plugin API;
- Hunspell Python/C++ binding;
- daemon/service;
- file watcher;
- settings store;
- document metadata;
- startup probe;
- dictionary downloader/installer.

The expected implementation owners remain:
- graphium/infrastructure/hunspell_session.py
- graphium/adapters/gtk/spelling.py
plus focused tests/docs/authority updates.
Application spell replacement semantics should not need a new domain/application
model solely for dictionary selection.

7. SECURITY / FAILURE CONTRACT
======================================================================

Discovery and selected dictionary handling must be fail-closed:
- executable path still resolved on demand;
- shell=False;
- discovery timeout bounded;
- discovery output byte budget bounded;
- number of accepted dictionaries bounded;
- candidate path length bounded;

- closing the GTK dialog during discovery or checking leaves no worker/child alive;
- no document pathname is ever passed to Hunspell.

9. PRE-IMPLEMENTATION RED/GREEN GATES
======================================================================

At minimum the implementation must establish focused gates for:

01. System-default argv remains without -d.
02. Explicit verified dictionary adds exactly one -d + base-path argv pair.
03. Dictionary path is shell-independent and protocol-safe.
04. -D discovery is on-demand only and LC_ALL=C.

16. Previously accepted Replace edits survive restart and remain Undo/Redo-normal.
17. External/unowned editor change cannot be masked by dictionary switching.
18. Close during discovery/check leaves no worker/Hunspell child.
19. No new persistent setting/config/document metadata is written.
20. No new dependency/module/framework and no GUI-language selector appears.
21. Full permanent Behavioral/Integration/Packaging-Release regression remains PASS.
22. Focused True-GTK probe, only if local qualification passes, proves real combo,
