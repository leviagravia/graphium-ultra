MATURE-SOURCE RE-COMPARISON

Findings relevant to cumulative structure:

1. Tab controls
   Mousepad owns a direct Tab Size action/submenu and a narrow Select Tab Size dialog. Leafpad/L3afpad
   also treat tab width as a direct editor control. Mature editors with large preference systems may duplicate
   such settings in Preferences; Graphium correctly rejects that duplication because it has no broad preference
   surface. G15-S2 erased the generic Preferences runtime instead of retaining a hidden second owner.

2. Hunspell dictionary selection
   FeatherPad directly validates a dictionary base and the companion .aff/.dic pair before constructing its
   Hunspell checker. Mousepad/gedit/GNOME Text Editor can delegate language enumeration and lifecycle to
   dedicated spelling libraries. Graphium deliberately retains its already-certified external Hunspell CLI
   boundary, so on-demand discovery needs its own bounded timeout/output/reap ownership rather than a new
   gspell/libspelling dependency or hard-coded distro dictionary paths.

   The S3 runtime growth is therefore classified ESSENTIAL COMPLEXITY for the selected architecture:
     - no new dependency;
     - no startup discovery;
     - no blocking GTK main-thread discovery;
     - no hard-coded distro path authority;
     - no new config/document metadata;
     - one existing worker only;
     - bounded external-process output/time/path/count;
     - explicit reap/cancel/stale fencing.

   Collapsing those guarantees merely to reduce LOC would reduce external-process and editor-state safety and
   is REJECTED as cosmetic simplification.

3. Application identity / About / legal
   Mature GTK editors use one stable application icon identity and standard About metadata fields. Graphium
   follows that pattern: S1 owns the application/default-window icon, and S5 does not create an About-specific
   logo authority. The project has one top-level LICENSE authority and uses standard Gtk.AboutDialog metadata.

4. Shortcuts
   Mature editors project accelerators through their existing command/action authority. Graphium adds no
   keyboard manager or chord subsystem; the two G15-S4 accelerators remain in the pre-existing CommandSpec
   authority with permanent negative collision oracles.
