2. USER-VISIBLE FAILURE
The user-provided screenshot of Help > About shows a tiny generic/missing-image
symbol rather than the Graphium application logo.

3. EXACT GRAPHUIUM SOURCE CAUSE
graphium/adapters/gtk/dialogs.py creates Gtk.AboutDialog and sets program name,
version, comments, authors, copyright, GPL license and repository, but does not
set either logo or logo-icon-name.

graphium/adapters/gtk/application.py correctly establishes the Graphium
application-icon authority:
  APPLICATION_ICON_NAME = io.github.leviagravia.Graphium
and sets:
  Gtk.Window.set_default_icon_name(APPLICATION_ICON_NAME)
plus a repo-local default icon list for source runs.

However, GtkAboutDialog's logo-icon-name property defaults to "image-missing";
logo-icon-name overrides logo. Therefore relying on the unset About properties
does not reliably project the application's default icon.

4. PREVIOUS ORACLE DEFECT
G15-S5 release test explicitly forbade:
  set_logo_icon_name
  set_logo(
  APPLICATION_ICON_NAME
in dialogs.py, assuming implicit default-window inheritance was sufficient.

The T480 probe then reported:
  ABOUT_APPLICATION_LOGO=PASS size=16x16

That assertion was insufficient: it proved only that a pixbuf existed, not that
the pixbuf was Graphium's logo. The screenshot demonstrates that the accepted
16x16 pixbuf was the missing-image/default placeholder.
